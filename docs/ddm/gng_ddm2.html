Introduction to Go/No-Go Drift Diffusion Models (Part 2)

This document is going to be an extension of the Introduction to Go/No-Go Drift Diffusion Models (Part 1) Github page. There are two main sections to this document. The first part discusses how to simulate Go/No-Go (GNG) data directly rather than transforming simulated two-choice data into a GNG, how to specify GNG prior distributions from the existing literature, and how to fit a GNG DDM along with model checking. In the second part, we fit GNG DDMs to a GNG task that was completed twice by me (Leo), where in one condition, I tried to do the task as quickly as possible and in another, as accurate as possible. These data along with their estimated DDM parameters are explored in this section.

Section 1

1. Correctly simulating GNG data

Like in the previous guides, we will only be fitting Wiener diffiusion models (WDM), which is a DDM where between-trial variability parameters (e.g., Sz, St0, SZ) are not estimated. Thus our model objects (emc objects to be specific) will have ‘WDM’ in the name.

1.1 Specifying a GNG WDM

We start by creating a model design object (‘emc.design’) using the design() function where we specify that we will be fitting a ‘DDMGNG’, what the factors of our dataset will be (e.g., esubjects, S), what the responses will be (“TO” is the reference so it will map to the lower boundary), our WDM specifications within formula, and additional information about what values within R correspond to a go vs a no-go response.

# Generating the model specifications for a GnG dataset
designWDMGNG <- design(model = DDMGNG,
                       factors=list(subjects=1, S=c("ng", "go")),
                       Rlevels = c("TO", "RESP"),
                       formula = list(a ~ 1,
                                      v ~ S, 
                                      t0 ~ 1,
                                      Z ~ 1),
                       functions = list(
                         TIMEOUT = function(d) rep(1.5, nrow(d)),
                         Rnogo  = function(d) factor(rep("TO",   nrow(d)), levels = c("TO", "RESP")),
                         Rgo    = function(d) factor(rep("RESP", nrow(d)), levels = c("TO", "RESP"))
                        ))

1.2 Choosing the GNG WDM parameter values

Here we use the sampled_pars() function to extract an empty vector of parameter names that will be estimated. We then choose what these values will be and confirm that we did this correctly with the mapped_pars() function.

# Choose parameters for simulation, first getting a vector with the right name
parsWDMGNG <- sampled_pars(designWDMGNG)

# Then choosing some values. Note that we include transforms here to illustrate
# the scale on which sampling occurs
parsWDMGNG[] <- c(log(1), -1, 4.2, log(.3), qnorm(.5))

# Confirm our parameters were specified correctly
mapped_pars(designWDMGNG, parsWDMGNG)

1.3 Simulating Racliff et al. (2018) GNG data

We are using Ratcliff et al. (2018) same data structure from their study to generate our GnG data. Their GNG task had 960 trials for each subject, where 720 trials were ‘go’ trials (75%) and 240 trials (25%) were ‘no-go’ trials. Thus we will do the same but just for one subject, as we will not be fitting hierarchical models in this document.

When simulating the data, we must make sure that all of our non-numeric variables are factors and not characters, and we must make the reference level consistent with the emc model object, such that “ng” and “TO” are the reference levels.

# Specify task structure
n_trials <- 960
prop_nogo <- 0.25

# Calculate number of Go and No-Go trials
n_nogo <- round(n_trials * prop_nogo)
n_go   <- n_trials - n_nogo

# Create simulation framework
GNG_framework <- data.frame(
  trials = seq_len(n_trials),
  subjects = factor(1),
  S = factor(
    sample(c(rep("go", n_go), rep("ng", n_nogo))),
    levels = c("ng", "go")
  ),
  R = factor(
    rep(NA_character_, n_trials),
    levels = c("TO", "RESP")
  )
)

# Simulate the gng data
gng <- make_data(data = GNG_framework,
                 parameters = parsWDMGNG, 
                 design = designWDMGNG)

# Specify the prior means in the transformed scale
pmean <- c(
  a = log(1.31), 
  v = -1.8, 
  v_Sgo = 2.5,  
  t0 = log(.38),
  Z = qnorm(.57) 
)

2.2 Specifying prior standard deviations for a GNG

In the introduction to the DDM document, we used the following rule to calculate prior standard deviations (a heuristic):

\[ SD = \frac{\text{MAX} - \text{MIN}}{4}\] The problem is, when we did that we had estimates nicely summarized for us from a study that reviewed 23 DDM studies. In our case, we reported parameter estimates from literally 4 studies- thus using the formula above, while informative, might lead us to have very restricted ranges. Instead, what we can do is keep the same logic but change the denominator from 4 down to 2 for now, until there are more studies available or someone nicely summerizes it all for us.

\[ SD_{GNG} = \frac{\text{MAX} - \text{MIN}}{2}\]

boundary separation (a): (log(1.620) - log(0.990))/2 = 0.25 non-decision time (Ter): (log(0.474) - log(0.253))/2 = 0.31 relative-starting point (Z): (qnorm(0.691) - qnorm(0.402))/2 = 0.37

We purposly kept the drift rates wide (2.5) rather than using the formula above, just in case we have very poor performers in our datasets. The same decision was made when specifying the prior distribution for the 2C DDM.

# Standard deviations for the GNG priors
psd <- c(
  a = 0.25,     # Spread for log(a)
  v = 2.5,     # Spread for drift rate v (ng)
  v_Sgo = 2.5,  # Spread for drift rate v (go)
  t0 = 0.31,   # Spread for log(t0)
  Z = 0.37     # Spread for probit(Z)
)

2.3 Creating the GNG prior distributions

With the means and standard deviations coded for, we can now use the prior() function to generate our priors. Additionally, we also specify that this is for a non-hierarchical model.

# Creating the prior distribution for each GNG WDM parameter
priorWDMGNG <- prior(designWDMGNG,
                     pmean=pmean, 
                     psd=psd,
                     type="single") # Non-hierarchical

5.2 Creating a model design that can be fit to the combined datasets

Here we are using the design() function to specify a model more complicated that we are used to. It is technically still a Wiener Diffusion Model since we are not estimating any of the between-trial variabiliaty parameters. However, here we are modeling every parameter as a function of E, which is essentially the condition factor with the speed and accuracy date. Additionally, the S * E interaction will allow us to estimate four drift rates, essentially a go and no-go drift rate for the speed and accuracy data.

# Creating the model design for the combined dataset
designWDMGNG_combined <- design(
  model = DDMGNG,
  factors = list(subjects = 1, S = c("ng", "go"), E = c("spd", "acc")),
  Rlevels = c("TO", "RESP"),
  LT = LT, # Removed trials shorter than this rt
  formula = list(
    a  ~ E,        # Boundary varies by Speed vs. Accuracy emphasis
    v  ~ S * E,    # Drift rate varies by Stimulus type AND Emphasis
    t0 ~ E,        # Non-decision time allowed to vary by Emphasis
    Z  ~ E         # Relative starting point allowed to vary by Emphasis
  ),
  functions = list(
    TIMEOUT = function(d) rep(1.5, nrow(d)),
    Rnogo   = function(d) factor(rep("TO",   nrow(d)), levels = c("TO", "RESP")),
    Rgo     = function(d) factor(rep("RESP", nrow(d)), levels = c("TO", "RESP"))
  )
)

5.3 Understanding the parameters that will be estimated

While we have used the mapped_pars() function multiple times to check whether or not we specified our parameters correctly when simulating data, we can also use this function to assess how parameters will be estimated as a function of factors in the data.

By default, the model uses dummy coding when estimating parameters, such that there is one level that functions as a reference. Therefore, the parameter for that reference level will be estimated, while the other levels have specific effects, or differences relative to the reference level, estimated instead. In our case, since we are modeling all parameters as a function of E, the ‘spd’ level functions as the reference. Thus, the baseline parameter corresponds to the ‘spd’ condition, while coefficients involving ‘acc’ instead represent the effect, or difference, associated with the accuracy condition. This is consistent across a, t0, and Z.

For drift rate, we additionally have an S * E interaction. Because ‘ng’ and ‘spd’ are the reference levels, v corresponds to the drift rate for ng trials in the ‘spd’ condition. The v_Sgo parameter represents the difference between go and ng trials within the ‘spd’ condition, while v_Eacc represents the difference between the accuracy and speed conditions for ng trials. Finally, v_Sgo:Eacc is the interaction effect, representing the additional change in the go versus ng difference under the accuracy condition beyond the two main effects.

5.4 Creating our prior distributions

Now we need to discuss how we will be creating the prior distributions for this more complex model specification of the GNG WDM. First, we need to differentiate the baseline parameters from the condition-effect parameters. Starting with the baseline parameters, these correspond to the reference levels of the factors in the model. For example, we know from the mapped_pars() output that the reference level for E is ‘spd’. Thus, the boundary separation (a), non-decision time (t0), and relative starting point (Z) baseline parameters correspond to the ‘spd’ condition, while the baseline drift rate (v) specifically corresponds to ng trials in the ‘spd’ condition. Therefore, we can treat these baseline parameters as we would parameters when they are specified to 1 (e.g., a ~ 1) by using the same prior means we already established.

For coefficients representing condition effects, such as those involving the ‘acc’ level, the parameter instead represents an effect or difference relative to the reference condition. Based on the approach used in Day1-BasicEAMS/2-Dual.R, these effects can have priors specified with a mean of 0 because we are not assuming a direction for the effect. This also applies to the interaction term. One exception is v_Sgo, which is technically an effect representing the difference between go and ng drift rates within the ‘spd’ condition. However, because we already established an informed prior for this go versus ng difference when specifying our original GNG WDM, we retain that prior rather than centering it at zero.

For our prior standard deviations, we again retain the values we previously established for the baseline parameters. For the condition-effect parameters, there is no straightforward rule for selecting a standard deviation. Following the approach used in Day1-BasicEAMS/2-Dual.R, we use somewhat smaller standard deviations for these effects, reflecting a vague expectation that condition effects will generally be smaller than the broader range of plausible values for the underlying parameters. The exact standard deviations chosen for these effects should therefore be viewed as weakly regularizing prior choices rather than empirically established values.

# Specify prior means
pmean <- c(
  a            = log(1.31),
  a_Eacc       = 0,
  v            = -1.80,
  v_Sgo        = 2.50,
  v_Eacc       = 0,
  "v_Sgo:Eacc" = 0,
  t0           = log(0.38),
  t0_Eacc      = 0,
  Z            = qnorm(0.57),
  Z_Eacc       = 0
)

# Specify prior standard deviations
psd <- c(
  a            = 0.25,
  a_Eacc       = 0.20,
  v            = 2.50,
  v_Sgo        = 2.50,
  v_Eacc       = 1.00,
  "v_Sgo:Eacc" = 1.00,
  t0           = 0.31,
  t0_Eacc      = 0.20,
  Z            = 0.37,
  Z_Eacc       = 0.25
)

# Create prior
priorWDMGNG_combined <- prior(
  designWDMGNG_combined,
  pmean = pmean,
  psd   = psd,

)
